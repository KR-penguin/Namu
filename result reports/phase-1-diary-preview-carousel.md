# A. 무엇을·왜

고정 4:5 미리보기에 모든 본문 블록을 한꺼번에 넣고 잘라내던 구조를, 블록 순서를 유지하며 좌우로 넘길 수 있는 4:5 다중 페이지 캐러셀로 바꾸었다. 긴 글은 현재 카드 크기와 시스템 글자 크기를 기준으로 실제 높이를 측정해 다음 페이지로 나누고, 사진은 본문 폭의 대부분을 쓰도록 확대했다. 현재/전체 페이지 표시와 이전·다음 버튼을 두어 터치, 키보드, 데스크톱 검토 환경에서 모두 넘길 수 있게 했다.

# C. Critical Path

- 글 잘림: 본문에 `maxLines`/ellipsis를 적용하지 않고 `TextPainter`로 가용 높이를 측정해 페이지를 나눈다. 이모지 조합 문자를 가능한 분리하지 않는 단위로 취급하고, 단어 경계를 우선해 나눈다.
- 순서 정합성: 공유 렌더러와 동일하게 원본 `DiaryBlock` 순서를 그대로 소비한다. 미리보기의 화면 크기와 글자 크기는 공유 PNG와 다르므로 페이지 수가 항상 같다고 가정하지는 않는다.
- 접근성: 페이지 번호는 live region으로 알리고 이전·다음 버튼에 tooltip을 두었다. PageView 안에서도 사진 의미 노드가 본문과 합쳐지지 않도록 별도 컨테이너로 유지했다.
- 회귀 검증: 긴 글·대형 사진·작은 화면·2배 글자 크기를 포함한 `diary_preview_panel_test.dart` 10개와 해당 코드 analyzer가 통과했다. `test/app/namu_app_test.dart test/features/diary` 회귀 묶음 111개도 모두 통과했다.

# D. 새로 도입한 것

- 추가 라이브러리 없이, 현재 카드 크기·locale·text scale에 맞춰 본문을 측정하는 미리보기 페이지네이터와 `PageView` 캐러셀을 도입했다.
